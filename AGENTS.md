# AGENTS.md — Astra Voice Assistant

## Проект

Astra — существующий русскоязычный голосовой ассистент для Windows. Основная платформа сейчас: Windows 10 Pro, Python 3.12, Windows PowerShell 5.1. Корневой runtime — `main.py`; прикладные контроллеры — в `src/`; проверки — в `tools/`.

Отвечай пользователю по-русски. Не переписывай проект с нуля и не меняй стек без доказанной необходимости.

## Перед любой работой

1. Выполни `git status --short --branch` и учти пользовательские изменения.
2. Прочитай затронутые файлы и релевантные тесты.
3. Не показывай содержимое `.env`, ключей, токенов или приватных данных.
4. Для v1.3 R3 помни: локальные изменения могут отсутствовать в GitHub; GitHub не является более свежим источником автоматически.

Запрещены без прямого поручения: `git reset --hard`, `git clean`, принудительный checkout, destructive rebase, удаление рабочего дерева, замена репозитория новым клоном.

## Реализация

- Сохраняй wake-only как безопасный режим по умолчанию.
- Не передавай произнесённый текст в shell, PowerShell, `cmd`, имя процесса, путь к executable или WinAPI без строгого разрешения и валидации.
- Прямые действия должны идти через типизированные команды и контроллеры, не через свободный ответ LLM.
- Не добавляй широкие allowlist-шаблоны ради прохождения одного примера.
- Все таймеры, повторения и многошаговые действия должны иметь конечные пределы.
- При ошибке сообщай правду; не имитируй успешное действие.
- Сохраняй совместимость с PowerShell 5.1, если изменение явно не вводит новый системный baseline.
- Используй UTF-8 и не создавай mojibake в русских строках.

## Файловые навыки

Файлы пользователя доступны только через capability grants: корень, разрешённые операции, срок и уровень подтверждения. Проверяй канонический путь и reparse/symlink непосредственно перед операцией.

- Чтение и поиск — только в разрешённых корнях.
- Запись — атомарная, с резервной копией при перезаписи.
- Удаление — через корзину по умолчанию.
- Массовые операции — сначала preview со счётчиком и примерами.
- Системные папки, секреты, SSH/GPG, браузерные профили и хранилища учётных данных запрещены по умолчанию.
- Фраза пользователя не должна сама расширять права текущей операции; выдача нового права — отдельное явное действие UI.

## Git и GitHub

- Локально разрешены status/diff/log и подготовка изменений.
- Коммит выполняй только когда пользователь поручил его или явно одобрил готовый diff.
- Push, force-push, merge, release, публикация артефактов и изменение issues/PR требуют явного подтверждения.
- Никогда не добавляй `.env`, ключи, токены, логи с личными данными, локальные пути пользователя и кэши.
- Перед коммитом: `git diff --check`, полный релевантный gate, `git status --short`, проверка staged diff и секретов.
- `main` должна оставаться защищённой; разработка — в ветках `codex/<краткая-тема>`.

## Тестирование

Минимум для изменения:

1. компиляция затронутого Python-кода;
2. узкие тесты изменённого поведения;
3. регрессионные smoke-тесты зависимых функций;
4. config validators и `astra_doctor.py`, когда затронута конфигурация/runtime;
5. ручной Windows gate для микрофона, TTS, окон, медиа, автозапуска и реальных приложений.

Не заменяй ручной тест утверждением на основе mock-теста.

## Критерий завершения

Задача завершена, когда код, тесты и документация согласованы; проверки пройдены или честно перечислены как недоступные; diff не содержит случайных изменений/секретов; пользователь получил список файлов, тестов, рисков и следующий шаг.
