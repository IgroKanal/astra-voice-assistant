# Точные критерии следующих beta

Статус 2026-11-14: текущая рабочая сборка — **Astra 3.0 Beta**, кандидат `3.0.0-beta.1`; релиз не опубликован. Этапы `1.4.0-dev.1–31` сохранены в истории и вошли в 2.0 Beta. Версии 2.1–2.9 закрывают выполненные продуктовые изменения. Отдельный этап 2.10 не выпускается: его улучшения локального ответа объединены с конечными тайм-аутами и замерами STT/TTS в 3.0. Ревизия `f702b8c` прошла полный GitHub Windows CI `43519298184`, включая portable-сборку и проверку provider-модуля в runtime EXE. Голосовая личная память прошла полный локальный gate: compileall, 252 unit/integration/UI теста, 10 smoke tests, 4 config validators и Astra Doctor. Реальные голосовые проверки, end-to-end p50/p95 и CI для этой ревизии остаются открытыми.

В текущем preview уже есть постоянные текстовые напоминания с отменой/непрочитанными состояниями, нативный tray, вопросы по явно выбранным документам через локальный Ollama, прокручиваемый центр разрешений и безопасный отказ при гонке за новым именем файла между процессами. Это не закрывает проверку замен существующих файлов и подмены родительских каталогов. Произвольные фоновые рутины, семантический индекс, другие офисные/медиа форматы, полная доступность и ручная приёмка остаются отдельными задачами.

## Astra 3.0 Beta · быстрый и ограниченный голосовой контур

- [x] После подтверждённой wake-фразы фоновый warmup касается только установленной Ollama-модели; не скачивает модель и не активируется на случайной речи.
- [x] Короткий warmup отключаем (`OLLAMA_WARMUP_ON_WAKE=false`), запросы Ollama сериализованы, локальный ответ по умолчанию идёт без thinking.
- [x] STT ограничен сетевым тайм-аутом по умолчанию 12 секунд; TTS использует общий лимит 25 секунд для основного и резервного голоса. Значения можно менять в `.env`.
- [x] STT timing разделяет запись, сетевое распознавание и общий путь; строка замера не содержит transcript.
- [x] Edge TTS при cache miss не делает предварительную повторную генерацию; резервный голос получает только остаток общего временного бюджета.
- [x] Файловые поиск и чтение внутри плана проверяют отмену и общий временной budget между элементами обхода и этапами разбора PDF, DOCX, XLSX и PPTX; отдельный файловый системный/парсерный вызов нельзя прервать посередине.
- [x] Отмена или отзыв доступа в File RAG передаётся в чтение, отбор фрагментов и потоковый локальный запрос Ollama; отмена закрывает соединение, а частичный ответ не показывается.
- [x] File RAG отклоняет ссылки на невыбранные фрагменты, сохраняя проверку актуальности исходных файлов.
- [x] Голосовая фраза «отмени ближайшее/следующее напоминание» при наличии разрешения reminders атомарно отменяет только одно самое раннее активное напоминание; общая просьба не выбирает его автоматически.
- [x] Фраза «отмени напоминание про …» отменяет запись только при единственном совпадении активного заголовка; ноль совпадений и несколько совпадений оставляют хранилище без изменений.
- [x] Точные голосовые фразы списка напоминаний при наличии wake-фразы и разрешения reminders называют до трёх ближайших активных записей в локальном времени; озвучиваемый текст ограничен, содержимое не передаётся модели.
- [x] Напоминание можно назначить на точное местное время сегодня, завтра, послезавтра или в ближайший указанный день недели, произнеся время словами или цифрами; если время в текущий день недели уже прошло, выбирается следующий такой день. Неверные часы/минуты и пустая формулировка остаются локальным отказом.
- [x] Локальный gate после проверок отмены, ссылок и напоминаний: compileall, 232 unit/integration/UI теста, 10 smoke tests, 4 config validators и Astra Doctor.
- [x] `tools/latency_report.py` агрегирует p50/p95 только для уже залогированных этапов STT/LLM/TTS, выводит одни числа и не выдаёт их за wake-to-first-audio.
- [x] Отмена файлового поиска, разбора и отзыв доступа в File RAG прошли GitHub Windows CI `43493497060`, `43495159745` и `43496136563`, включая portable-package validation.
- [ ] Реальная проверка микрофона и голосов, а также p50/p95 от wake до первого звука остаются открытыми до проверки Егором.
- [ ] Приложение, UI, иконка и 2D/3D-персонажи не менялись; визуальная работа остаётся отдельному потоку/Kimi.

## v3.0 Beta

- [x] Явные зашифрованные локальные заметки: сохранить/найти/забыть.
- [x] Заметки подключены к локальному диалогу с явным согласием и отзывом; облачный путь не читает память.
- [x] Локальный Ollama и OpenAI-compatible провайдеры используют общий `TextProvider` для ответов и классификации; адаптеры не выполняют действия на ПК.
- [x] Privacy boundary сохранён: диалог и заметки подаются только локальному Ollama; ошибка локальной модели не запускает облачный запрос; отключённый провайдер не создаёт сетевой клиент.
- [x] Голосовые команды локальной памяти: сохранить, перечислить заголовки, найти заметку и забыть её только при единственном совпадении; обязательно wake-фраза, включённая личная память, выбранный локальный Ollama и отдельное разрешение; неоднозначность, отсутствие opt-in или отозванный grant не меняют базу; содержимое не отправляется в LLM и не записывается в action audit.
- [ ] Автоматическая маршрутизация между локальной и облачной моделью по чувствительности и сложности запроса, включая проверяемую offline-политику, остаётся открытой.
- [x] Базовый RAG по разрешённому UTF-8/PDF/DOCX/XLSX/PPTX документу через локальный Ollama; цитаты остаются недоверенными, есть injection tests для TXT/DOCX/XLSX.
- [ ] OCR/таблицы/остальные офисные форматы, семантический индекс и широкая eval-выборка.
- [x] Ограниченный локальный планировщик принимает только точную JSON-схему для files.search/files.read_text; невалидные поля, traversal, неизвестные навыки и управляющие символы блокируются.
- [x] В файловом UI локальная модель получает запрос только после отдельного согласия; документы ей не передаются. План требует симуляции актуальных шагов и отдельного подтверждения.
- [ ] Реальная Ollama-модель должна пройти пользовательскую оценку качества запросов; общие desktop actions, risk scoring и долгие budgeted workflows не реализованы.
- [ ] Рутины, фоновые задачи и уведомления с отменой.
- [ ] Eval-набор реальных пользовательских команд.
