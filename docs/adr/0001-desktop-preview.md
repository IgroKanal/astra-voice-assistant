# ADR 0001 — desktop preview поверх существующего runtime

Дата: 2026-11-12. Статус: принято для preview, допускает пересмотр UI-стека.

## Контекст

Пользователь поручил начать автономное развитие до v5.0 Beta и первым делом уйти от ручного запуска через PowerShell. Существующая v1.3 R3 незакоммичена; менять всё ядро сразу нельзя. Ручные микрофон/медиа проверки пользователь выполнит позже.

## Решение

- Tk используется для первого работоспособного окна: он уже доступен в Python и позволяет быстро получить локальное приложение.
- `main.py` остаётся worker runtime. UI связывается с ним через stdin/stdout pipe и типизированные JSON events v1.
- Процессная граница изолирует UI от блокирующих STT/TTS/LLM операций.
- PyInstaller собирает отдельные Astra.exe (UI) и AstraRuntime.exe (worker). Preview переносимый, без установки и повышения прав.
- Конфигурация приложения лежит рядом со сборкой; личный .env не упаковывается.
- Микрофон выключен по умолчанию. Голос включается явной кнопкой.
- Файловая область выдаётся пользователем на сессию через выбор папки. Текст/PDF/DOCX/XLSX/PPTX читаются локально; каждая операция записи имеет отдельное временное разрешение, preview и подтверждение.
- Многошаговые файловые планы выполняются через SkillExecutor с явными схемами и ограничением шагов.
- Явная память заметок шифруется DPAPI и хранится отдельно от distributable в LocalAppData.

## Последствия

Пользователь уже получает приложение, а работающий runtime сохраняется. UI может позднее перейти на PySide6 или WinUI без переноса доменной логики. Сейчас подтверждены Tk callback tests и offline frozen runtime, но визуальное качество, микрофон и реальные media/windows требуют отдельной проверки.

Текущий UI не является финальным дизайном; DPAPI не является межустройственной синхронизацией; восемь read-only шагов не являются неограниченным агентом. Миграция всех навыков к единому policy engine остаётся обязательной работой.
