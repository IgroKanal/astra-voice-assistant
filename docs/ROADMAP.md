# Дорожная карта до v5.0 Beta

Текущий рабочий этап — **Astra 3.1**, локальная сборка 3.1.0 без публикации; содержательные изменения v3.2 выполняются в `codex/adaptive-microphone-identity` (последний проверенный commit `e6b328d`). Полный локальный gate этой ревизии прошёл: 637 тестов, 1 штатный пропуск, 9 smoke-проверок, compileall, 4 config validators и Astra Doctor. GitHub Actions не показывает запуска для текущей головы ветки; опубликованные ниже CI-запуски относятся к более ранним ревизиям и не заменяют проверку этой головы. Реальные документы, микрофон, качество голоса и p50/p95 wake-to-first-audio остаются открытыми до пользовательской приёмки. Этапы 1.4.0-dev.1–31 вошли в 2.0 Beta; версии 2.1–2.9 закрыли отдельные продуктовые этапы. Общие критерии v2–v5 остаются открытыми до своих gates.

Продуктовые этапы 2.x завершены на 2.9; подготовка установленной Ollama-модели после wake-фразы была промежуточной работой и вошла в этап 3.0.

Направление персонажа по просьбе Егора: аниме-образы мужского и женского рода с отдельными именами и голосами; имя можно заменить своим. В 1.4.0-dev.6 встроены четыре оригинальных 2D-портрета (две женские и две мужские личности), а DPAPI-профиль хранит отдельное имя и голос каждого. В dev.7 добавлен живой preview портрета/имени до сохранения. В dev.14 настройки запустили отдельное 3D-preview окно для несохранённого выбора; в dev.15 оно синхронизируется с пятью состояниями desktop-приложения по аутентифицированному loopback-каналу. Переносимый ZIP включает Godot 4.7.2 и лицензионные notices. Модель процедурная и пока не polished; остаются визуальная приёмка, GPU/performance, полноценный rig, lip-sync и интеграция 3D в основное окно.

## Phase 0 — принятие и сохранение v1.3 R3

Цель: не потерять существующую работу и получить воспроизводимую базу.

- инвентаризация dirty worktree и зависимостей;
- резервный patch/bundle или защищённая рабочая ветка;
- полный автоматический и ручной gate;
- устранение найденных регрессий;
- review безопасности;
- коммит v1.3 R3 после одобрения пользователя;
- push/release отдельно и только по разрешению.

Готово, когда репозиторий воспроизводим, рабочее дерево понятно, тесты зелёные, ручные ограничения зафиксированы.

## v2.0 Beta — надёжное ядро и система навыков

Цель: отделить понимание команды от исполнения и подготовить расширение без хаоса в `main.py`.

- типизированные `Intent`, `ActionPlan`, `ActionResult`;
- реестр навыков и единый policy/permission engine;
- event bus и конечный автомат сессии wake/follow-up;
- структурированные логи с correlation ID и редактированием личных данных;
- конфигурация со схемой и миграциями;
- Файловые навыки: поиск и чтение UTF-8, PDF, DOCX/XLSX/PPTX и ODT/ODS/ODP с локальной RAG-выборкой; ODF добавлен в Astra 3.1 через ограниченный read-only XML-разбор без распаковки на диск. Копирование, перемещение, переименование, создание пустых папок, отдельные grants, previews и отменяемые планы уже поддерживаются; OCR, старые Microsoft Office-форматы, медиа-расшифровка и более широкая обработка папок остаются открытыми;
- capability grants для пользовательских корней;
- preview и корзина для удаления;
- первая безопасная операция «В Корзину Windows» реализована в 1.4.0-dev.5: отдельный grant, preview, подтверждение и hardlink блокировка;
- создание пустых папок в выбранном workspace добавлено в 1.4.0-dev.8: отдельный write grant, preview/confirmation, durable journal, откат сохраняет пустую папку в `.astra-history` и отказывается затрагивать папку с пользовательским содержимым;
- pytest-основа, unit/integration/contract tests;
- CI: compile, smoke, configuration validators, unit/integration tests, portable build, package secret/forbidden-file scan, CRC, встроенные аватары и relocated-runtime check заданы в Windows workflow. Windows CI для базы `f702b8c` прошёл (`43519298184`); новые изменения требуют отдельного запуска CI после отправки в рабочую ветку.

Gate: LLM не может обойти policy engine; path traversal/reparse tests; старые voice-команды не регрессируют; операции восстанавливаемы.

## v3.0 Beta — умный ассистент и автоматизация ПК

Цель: многошаговые полезные задачи с контролируемой автономностью.

- planner/executor с лимитами шагов, времени и стоимости;
- первый фоновый сценарий: отдельная bounded-очередь вопросов к явно выбранному локальному Ollama, без контекста диалога и личных заметок; три задания максимум, один inference worker, лимит выполнения 180 секунд и сетевого ожидания 30 секунд, получение статуса/результата/отмена голосом, поток Ollama закрывается по отмене; вопрос и ответ остаются в памяти процесса и не попадают в файлы или логи;
- файловые поиск и чтение внутри плана проверяют общий deadline и отмену пользователя во время обхода каталога и между страницами PDF, узлами DOCX, ячейками XLSX и слайдами PPTX; отдельный системный I/O или вызов парсера нельзя прервать посередине, OCR и длинные сетевые операции требуют своих адаптеров;
- отзыв доступа или отмена локального вопроса по выбранным файлам передаётся в чтение и лексический отбор фрагментов; если пользователь отменил во время чтения, запрос к Ollama не начинается; уже начатый сетевой вызов модельного сервера до ответа не прерывается;
- безопасная API-симуляция read-only плана без файлового I/O добавлена в 1.4.0-dev.11; preview явно не выдаёт capability grant и не авторизует исполнение;
- локальный Ollama и OpenAI-compatible провайдеры подключены через общий интерфейс `TextProvider`; `AIClient` отвечает за prompts, историю, тайминги и разбор результата, а адаптеры — только за текстовую генерацию; явный выбор ровно одного провайдера сохраняется, неявного переключения локальной модели в облако нет; автоматическая маршрутизация локально/облако по типу задачи остаётся открытой;
- явная маршрутизация команд через установленный локальный Ollama добавлена в Astra 2.9 Beta; opt-in выключен по умолчанию, облачного fallback нет, а typed action проходит общий ActionPolicy; оценка качества модели и распознавание голосом остаются открытыми;
- быстрый путь локальной модели: короткий warmup после проверенной wake-фразы выполняется в фоне только для установленной модели; отсутствующая модель не скачивается, запросы сериализованы, настройка отключения — `OLLAMA_WARMUP_ON_WAKE=false`;
- STT задаёт конечный сетевой тайм-аут, а диагностика разделяет захват микрофона, запрос распознавания и полное время без текста распознанной команды;
- сбой захвата или закрытия аудиопотока вызывает до двух попыток заново инициализировать выбранный микрофон и проверить захват; при неуспехе голосовой режим завершается с понятной ошибкой вместо бесконечного цикла. Обычные тайм-ауты ожидания речи не отключают устройство. Реальное переподключение микрофона и задержки драйвера требуют ручной проверки;
- Edge TTS имеет конечный общий бюджет ожидания для основного и резервного голоса; дополнительный синтез при промахе кэша не запускается. Windows SAPI и приватное чтение документов записывают длительность локального воспроизведения без текста речи;
- timing локального/облачного LLM, Edge TTS и SAPI даёт опорные точки для измерения, но личные p50/p95 полного контура и реальная голосовая приёмка ещё не выполнены;
- `tools/latency_report.py` локально агрегирует p50/p95 существующих STT/LLM/TTS timing-записей и отдельно группирует TTFT по провайдерам, не выводя содержимое логов; задержка wake → первый слышимый звук остаётся отдельным ручным измерением;
- память: профиль, предпочтения, эпизоды и явное забывание; голосовые команды сохранения, списка, поиска и удаления единственной совпавшей заметки добавлены локально, только после wake-фразы, отдельного opt-in личной памяти и разрешения «Голосовое управление личными заметками»; неоднозначное удаление ничего не меняет;
- голосовые файловые навыки: поиск имён требует wake-фразы и отдельного выключенного по умолчанию `files`, действует только внутри выбранной папки, пока окно «Файлы» открыто, и ограничен 10000 элементами/500 совпадениями/8 секундами. Открытие требует отдельного `open_files`, точного единственного имени и безопасного типа; ссылки и исполняемые файлы отклоняются. Чтение реализовано отдельной командой и default-deny `read_files`: точное имя в выбранной папке, текстовые/конфигурационные/исходные UTF-8, BOM-marked UTF-16 и CP1251 файлы, HTML/HTM плюс PDF/DOCX/XLSX/PPTX, отрывки до 1600 символов, только локальный Windows SAPI; текст не попадает в чат/LLM/облачный TTS, а исходные скрипты и HTML нельзя запустить этой командой. Ручная голосовая приёмка остаётся открытой;
- базовый RAG по разрешённым UTF-8/HTML/HTM/PDF/DOCX/XLSX/PPTX файлам через явно выбранный локальный Ollama с injection тестами для цитат; сравнение до пяти явно выбранных файлов с общим лимитом размера, проверкой актуальности и file/line citations реализовано; семантический индекс, OCR и дополнительные форматы остаются открытыми;
- планировщик рутин и триггеров;
- расширенные браузерные и desktop-навыки через типизированные адаптеры;
- уведомления, отмена, пауза и журнал действий; в 3.0 Beta голосом можно создать напоминание через срок, на конкретное локальное время сегодня/завтра/послезавтра или в ближайший день недели (часы и минуты цифрами или словами), запросить список ближайших, отменить одно следующее или отменить единственную запись по точному фрагменту названия; при нескольких совпадениях Astra просит уточнить. Операции работают с локальным хранилищем при wake-фразе и разрешении reminders;
- оценка уверенности и запрос уточнения только при реальной неоднозначности;
- UI для планов реализован в 1.4.0-dev.12; в dev.13 локальный Ollama предлагал строгий read/search JSON-план, dev.16 добавил copy/move, dev.17 добавил rename в той же папке и создание пустой папки. Текст запроса передаётся только после отдельного согласия и только явно выбранному локальному Ollama. Симуляция не читает и не меняет файлы; для всех изменений нужны временный write grant, точный transaction preview и отдельное подтверждение. Delete/overwrite моделью не разрешены. Общие desktop-навыки, автоматическое понимание контекста и реальная оценка качества Ollama остаются открытыми.

Gate: prompt injection из документов не расширяет права; действия идемпотентны или компенсируемы; пользователь видит, что Astra сделала и почему.

Статус 3.0: автоматические проверки голосового пути проходят локально. Beta остаётся кандидатом до проверки реального микрофона, субъективного качества голосов, p50/p95 и GitHub CI. Приложение и аватары не меняются в этом этапе.

## v3.2 — быстрый голос и расширение возможностей ядра

Цель: Astra должна быстрее отвечать голосом и уметь выполнять более широкий круг пользовательских задач через типизированные навыки, не отдавая модели прямое управление системой.

- [x] Потоковые ответы OpenAI-compatible провайдера: показывать токены по мере генерации и запускать озвучивание первого безопасного законченного предложения до готовности всего ответа.
- [x] Записывать задержку до первого токена для потокового ответа без записи текста вопроса или ответа в журнал.
- [x] Изолировать ошибку раннего воспроизведения от генерации: сбой callback не должен обрывать итоговый ответ.
- [x] Поддержать отмену потокового OpenAI-compatible ответа через `AIClient.ask(cancelled=...)`: закрывать поток, не отдавать токены после отмены, не записывать частичный ответ в cloud dialogue и не переходить к fallback-модели. Тайм-аут провайдера ограничивает ожидание начала потока.
- [x] Если пользователь не выбрал SAPI-голос явно, предпочитать установленный русский голос с метаданными, совпадающими с полом активного персонажа; сохранённый ID остаётся главным, а при отсутствии совпадения сохраняется русский fallback.
- [x] Завершать раннее воспроизведение перед сообщением об ошибке потока и сохранять контроль над ещё играющим TTS после тайм-аута; следующий ответ не должен накладываться на него. Если облачный поток уже передал фрагмент обработчику, не смешивать его с ответом запасной модели; до первого фрагмента запасная модель по-прежнему доступна.
- [x] В ошибках облачного ответа и классификатора записывать тип и HTTP-статус без текста исключения провайдера, который может содержать запрос или секреты; это проверяется отдельными тестами.
- [x] Распознавать установленный шаблон Qwen3, который принудительно открывает `<think>` даже при выключенном режиме рассуждений: запрашивать у Ollama отдельный канал рассуждений и не озвучивать его. При исчерпании лимита объяснять, что этой модели может понадобиться более быстрая замена; остальные шаблоны сохраняют выбранный режим. Это защита конкретного выявленного шаблона, а не гарантия для всех моделей.
- [x] Сравнить на этом ПК небольшую `qwen2.5:0.5b-instruct` без автоматического выбора: после загрузки первые фрагменты в нескольких коротких запросах приходили примерно за 0,46–0,79 с, но модель ошибалась в простых вопросах, выдумала текущую погоду и не удержала имя в диалоге. Считать её неподходящей для роли основного ассистента; замеры не включают микрофон и озвучку.
- [ ] Проверить реальную задержку p50/p95 от wake-фразы до первого звука на Windows и настроить потоковый путь по результатам.
- [x] Добавить `FileWorkspaceGroup` для до 16 явно выбранных папок: поиск, точное имя, безопасное чтение и локальный RAG используют относительные пути с меткой корня и повторно проверяют каждый корень.
- [x] Добавить основу `FileWorkspaceGrant`: отдельный root grant перечисляет разрешённые операции, истекает не позже 24 часов, может быть отозван немедленно и повторно проверяется во время долгого чтения/поиска; для локальных вопросов по файлам требуется отдельная операция `ask`.
- [x] Добавить транзакционный слой записи в несколько выбранных корней: для каждой папки нужны отдельный `write` scope и отдельное временное включение; каждый одноразовый preview привязан к точной типизированной операции плана и повторно проверяет состояние файлов; планы проверяют все previews до первого изменения и отклоняют пересекающиеся шаги. Между корнями разрешено бинарное копирование до 16 МБ с `read` на источнике, `write` на назначении и ограниченным объёмом ожидающих копий; межкорневое перемещение пока запрещено.
- [x] Добавить типизированную операцию `files.trash` для переноса в Корзину: отдельный `trash` grant на выбранную папку, точный одноразовый preview и повторная проверка до операции; обычное разрешение записи не открывает удаление. Локальный планировщик может предложить её только после явного запроса, а файловый экран показывает путь/размер и просит подтверждение; постоянное удаление недоступно. Прямой голосовой парсер не запускает удаление.
- [x] Голосовая команда «создай пустую папку …» использует относительный путь, отдельные `modify_files` и root write-grant, точный preview и одноразовое подтверждение; создание можно отменить через существующий undo.
- [x] Точные wake-only фразы отмены файлового действия ведут только в typed `FILE_MUTATION/undo`, без LLM; undo доступен для последней подтверждённой voice copy/move/mkdir в текущем runtime, повторно проверяет grants и журнал транзакций, а успешное перемещение в Корзину очищает undo-указатель.
- [x] Экспортировать единый неизменяемый каталог разрешений для permission center приложения с русскими названиями, пояснениями и фактическими default-состояниями; policy отклоняет некорректные наборы разрешений, повреждённые source/confidence-поля и недоверенные источники даже для действий без отдельного scope.

## После v5.0 Beta

Beta-линейка закрывается. Первый стабильный выпуск получает номер **Astra 1.0**, затем стабильные поколения **2.0, 3.0, 4.0…**. Старые номера `v1.x Beta` остаются в истории и не переименовываются.

Мобильное приложение начинается отдельной программой после стабилизации desktop core: сначала companion (уведомления/команды/статус), затем синхронизация разрешённых данных, позже — часть локальных навыков телефона.
