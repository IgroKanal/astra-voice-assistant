# Дорожная карта до v5.0 Beta

Текущая продуктовая версия — **Astra 2.7 Beta**, `2.7.0-beta.1`. Ночные сборки `1.4.0-dev.1–31` объединены в 2.0 Beta; их история сохранена. Версии 2.1–2.3 добавили последовательные UX-этапы, 2.4 укрепила обработку конфликтов файловых операций между процессами, 2.5 связала новый диалог в приложении с безопасным сбросом контекста runtime, 2.6 добавила поиск команд с безопасной вставкой примеров, а 2.7 улучшает поиск и фильтрацию в приватном журнале действий. Общие критерии v2–v5 остаются открытыми до выполнения своих gates.

Продуктовые этапы 2.x: 2.0 — типизированные действия и policy; 2.1 — единая тема, память и настройки; 2.2 — задачи и файловое окно; 2.3 — понятный центр разрешений и компоновка для небольших экранов; 2.4 — атомарный отказ при конкурентном создании занятого имени; 2.5 — подтверждаемый новый диалог, локальный сброс временного контекста и обновление интерфейса по событию runtime; 2.6 — поиск по каталогизированным командам и безопасная вставка; 2.7 — поиск и фильтр исходов в локальном журнале действий без показа пользовательского содержимого. Следующие номера будут присваиваться после заметных проверяемых этапов, а не каждому внутреннему изменению.

Направление персонажа по просьбе Егора: аниме-образы мужского и женского рода с отдельными именами и голосами; имя можно заменить своим. В 1.4.0-dev.6 встроены четыре оригинальных 2D-портрета (две женские и две мужские личности), а DPAPI-профиль хранит отдельное имя и голос каждого. В dev.7 добавлен живой preview портрета/имени до сохранения. В dev.14 настройки запустили отдельное 3D-preview окно для несохранённого выбора; в dev.15 оно синхронизируется с пятью состояниями desktop-приложения по аутентифицированному loopback-каналу. Переносимый ZIP включает Godot 4.7.2 и лицензионные notices. Модель процедурная и пока не polished; остаются визуальная приёмка, GPU/performance, полноценный rig, lip-sync и интеграция 3D в основное окно.

## Phase 0 — принятие и сохранение v1.3 R3

Цель: не потерять существующую работу и получить воспроизводимую базу.

- инвентаризация dirty worktree и зависимостей;
- резервный patch/bundle или защищённая рабочая ветка;
- полный автоматический и ручной gate;
- устранение найденных регрессий;
- review безопасности;
- коммит v1.3 R3 после одобрения пользователя;
- push/release отдельно и только по разрешению.

Готово, когда репозиторий воспроизводим, рабочее дерево понятно, тесты зелёные, ручные ограничения зафиксированы.

## v2.0 Beta — надёжное ядро и система навыков

Цель: отделить понимание команды от исполнения и подготовить расширение без хаоса в `main.py`.

- типизированные `Intent`, `ActionPlan`, `ActionResult`;
- реестр навыков и единый policy/permission engine;
- event bus и конечный автомат сессии wake/follow-up;
- структурированные логи с correlation ID и редактированием личных данных;
- конфигурация со схемой и миграциями;
- файловые навыки v1: поиск; чтение UTF-8, searchable PDF, DOCX, XLSX и PPTX с локальной RAG-выборкой; копирование, перемещение, переименование файлов и создание пустых папок. Ограниченный локальный planner/executor поддерживает их с dev.17; ограниченный локальный просмотр JPEG/PNG/BMP/GIF/WebP без передачи в модель добавлен в dev.27. OCR и безопасное извлечение содержимого из изображений/сканов, старые Office-форматы и более широкая обработка папок остаются открытыми;
- capability grants для пользовательских корней;
- preview и корзина для удаления;
- первая безопасная операция «В Корзину Windows» реализована в 1.4.0-dev.5: отдельный grant, preview, подтверждение и hardlink блокировка;
- создание пустых папок в выбранном workspace добавлено в 1.4.0-dev.8: отдельный write grant, preview/confirmation, durable journal, откат сохраняет пустую папку в `.astra-history` и отказывается затрагивать папку с пользовательским содержимым;
- pytest-основа, unit/integration/contract tests;
- CI: compile, smoke, configuration validators, unit/integration tests, portable build, package secret/forbidden-file scan, CRC, встроенные аватары и relocated-runtime check заданы в Windows workflow. Workflow пока не запускался на GitHub, потому что изменения не отправлялись; локальная сборка и тот же package validator уже прошли.

Gate: LLM не может обойти policy engine; path traversal/reparse tests; старые voice-команды не регрессируют; операции восстанавливаемы.

## v3.0 Beta — умный ассистент и автоматизация ПК

Цель: многошаговые полезные задачи с контролируемой автономностью.

- planner/executor с лимитами шагов, времени и стоимости;
- безопасная API-симуляция read-only плана без файлового I/O добавлена в 1.4.0-dev.11; preview явно не выдаёт capability grant и не авторизует исполнение;
- локальные и облачные LLM-провайдеры через единый интерфейс;
- память: профиль, предпочтения, эпизоды, явное забывание;
- базовый RAG по разрешённым UTF-8/PDF/DOCX/XLSX/PPTX файлам через явно выбранный локальный Ollama с injection тестами для цитат реализован в 1.4.0-dev.10; сравнение до пяти явно выбранных файлов с общим лимитом размера, проверкой актуальности и file/line citations добавлено в dev.18; семантический индекс, OCR и дополнительные форматы остаются открытыми;
- планировщик рутин и триггеров;
- расширенные браузерные и desktop-навыки через типизированные адаптеры;
- уведомления, отмена, пауза и журнал действий;
- оценка уверенности и запрос уточнения только при реальной неоднозначности;
- UI для планов реализован в 1.4.0-dev.12; в dev.13 локальный Ollama предлагал строгий read/search JSON-план, dev.16 добавил copy/move, dev.17 добавил rename в той же папке и создание пустой папки. Текст запроса передаётся только после отдельного согласия и только явно выбранному локальному Ollama. Симуляция не читает и не меняет файлы; для всех изменений нужны временный write grant, точный transaction preview и отдельное подтверждение. Delete/overwrite моделью не разрешены. Общие desktop-навыки, автоматическое понимание контекста и реальная оценка качества Ollama остаются открытыми.

Gate: prompt injection из документов не расширяет права; действия идемпотентны или компенсируемы; пользователь видит, что Astra сделала и почему.

## v4.0 Beta — собственное Windows-приложение и голосовая личность

Цель: уйти от консольного ощущения к цельному приложению.

- Windows UI с tray, настройками и permission center; карточка первого запуска добавлена в dev.22, трёхшаговый wizard персонажа/ИИ/приватности — в dev.23, сохранение выбора «Пока пропустить» под DPAPI — в dev.24; voice capture и полная визуальная приёмка остаются открытыми;
- раздельные core service и UI process;
- локальный IPC с аутентификацией;
- аниме-аватары 2D: четыре встроенных мужских/женских профиля с разными именами/голосами и собственным именем ассистента готовы в 1.4.0-dev.6; live preview до сохранения готов в dev.7; синхронизация idle/speaking-портрета добавлена в dev.19; процедурные 3D-профили получили gender-формы и blink-анимацию в dev.31, polished production-модели и расширение выбора остаются открытыми;
- выбор и preview 2D/3D до сохранения: 2D встроен в настройки, dev.14 добавил отдельное окно, dev.15 синхронизирует его состояния с desktop UI по токенизированному loopback; production-модель, renderer в основном окне и performance ADR остаются открытыми;
- циклическая смена закрытого/открытого кадра на протяжении реального TTS-состояния добавлена в dev.20; lip-sync по анализу громкости, phoneme/viseme и точная синхронизация губ с аудио остаются открытыми;
- настройка голоса, скорости и эмоциональных профилей;
- tray-based явное включение и выключение микрофона добавлено в dev.25; push-to-talk и отдельный wake indicator остаются открытыми;
- диагностическая панель устройств и latency;
- user-level Inno Setup installer без UAC и с сохранением LocalAppData при uninstall добавлен и интеграционно проверен в dev.21; Windows CI настроен собирать и проверять portable ZIP и Setup, но сам GitHub run ещё не проверен; безопасные подписанные обновления с rollback остаются открытыми;
- tray-переключатель микрофона по явному клику добавлен в dev.25; защищённый парольной фразой переносимый экспорт/импорт AI-профиля — в dev.26; краткая индикация «слушает/распознаёт/думает/говорит» в tooltip — в dev.28; ручная проверка реального микрофона остаётся открытой;
- установщик и удаление без потери пользовательских данных: проверено локально в dev.21;

Gate: UI не зависает вместе с STT/LLM; микрофонное состояние всегда видно; background service не получает больше прав, чем нужно; обновление откатывается.

Решение по UI-стеку принимается отдельным ADR после прототипов (например, PySide6 против WinUI/.NET). Не выбирать стек только ради модного интерфейса.

## v5.0 Beta — интегрированная «правая рука»

Цель: последняя beta с цельным опытом и основой будущей экосистемы.

- polished 2D character и настраиваемая персональность;
- голос + текст + UI как единая сессия;
- зрелая система skills/plugins с подписанными манифестами;
- персональная память с экспортом, удалением и шифрованием: DPAPI backup/restore добавлен в dev.2, парольная переносимая копия памяти с импортом и повторным шифрованием под DPAPI нового ПК — в dev.29;
- автономные задачи с budget/policy/approval checkpoints;
- локальная модель для приватных/простых задач и облачная для сложных;
- резервные режимы без сети;
- телеметрия только opt-in;
- API/протокол синхронизации, подготовленный для мобильного клиента;
- backup/restore и миграция данных: переносимый AI-профиль добавлен в dev.26, переносимая память — в dev.29, перенос ожидающих/непрочитанных напоминаний — в dev.30; вложения/индексы и восстановление всей пользовательской папки остаются открытыми;
- accessibility, crash recovery, performance/security audit.

Gate: установщик, обновления, восстановление, privacy review, длительный soak test, beta feedback и отсутствие критических потерь данных.

## После v5.0 Beta

Beta-линейка закрывается. Первый стабильный выпуск получает номер **Astra 1.0**, затем стабильные поколения **2.0, 3.0, 4.0…**. Старые номера `v1.x Beta` остаются в истории и не переименовываются.

Мобильное приложение начинается отдельной программой после стабилизации desktop core: сначала companion (уведомления/команды/статус), затем синхронизация разрешённых данных, позже — часть локальных навыков телефона.
